Our Story

An honest account of why I built a coffee shop in Three.js — the creative process, the technical decisions, the things that broke, and the things I'm genuinely proud of.

01

The Concept

I spend a lot of time in coffee shops. Working, procrastinating, people-watching — there's something about that environment I've always found worth paying attention to. So when this assignment came around and I needed three models to showcase, it felt obvious to build BrewHaven around that world.

The name came from the idea of a coffee shop as a place you actually want to be — a haven, not just a caffeine stop. I wanted the whole project to feel like you're stepping inside a brand, not just clicking through a 3D demo. That shaped everything from the colour choices to the way I wrote the panel text.

The three objects I chose — an espresso machine, an coffee cup, and an ambient interior — each represent a different aspect of coffee shop culture. The machine is the craft, the drink is the product, and the interior is the atmosphere. I tried to let that logic drive the design decisions too.

02

The Craft

All three models are built procedurally in JavaScript using Three.js geometry — no external model files for the first two, and a GLB for the ambient interior. Every proportion, material value, and colour was a deliberate choice.

Espresso Machine

This was the most technically challenging model. I used BoxGeometry for the main body and built the control panel surface from 52 individual key meshes — each one placed by hand. The body material uses a custom GLSL ShaderMaterial I wrote myself, implementing Fresnel reflectance and an animated UV shimmer to get that brushed stainless steel look. The screen panel is a Canvas 2D texture I drew in code — it shows a pressure dial with tick marks and a live readout. The trackpad area uses MeshPhysicalMaterial with clearcoat set to 0.6, which gives it that polished glass-panel feel.

Coffee Cup

I wanted this model to have that tall, elegant proportions you get with a specialty café glass. I built it using LatheGeometry, defining my own 2D profile curve to get the slight taper and rounded base. The label texture is generated at runtime using the Canvas 2D API — it includes a shimmer gradient, glitter dots, and my own branding. The material is MeshPhysicalMaterial with clearcoat: 1.0 and near-zero roughness, so it reads as high-gloss. The gold straw is a thin cylinder with a sphere tip, both of which can be animated to extend using the controls panel.

Coffee Shop Interior

This one is more abstract than the other two. I loaded a GLB file of a sphere and used it to represent the ambient atmosphere of a café — the warm glow, the sense of being enclosed in a space that feels good. The DoubleSide material flag was important here because without it you'd get black patches where the inside faces weren't rendering. The Glow toggle uses a PointLight positioned in front of the mesh rather than emissive intensity, which gives a more natural, diffuse illumination. The phase toggle swaps between two pre-built geometry states in the GLB to change how the light falls — it's a loose interpretation of morning vs evening atmosphere in a café.

03

Under the Hood

The app runs entirely in the browser with no server-side dependencies.

Three.js r128 HTML5 Canvas API CSS3 JavaScript ES6 jQuery 3.7 GLSL Shaders WebGL Google Fonts GLTFLoader

Three.js

I chose Three.js over X3DOM because it has much more active development, better documentation, and proper support for physically-based materials. The scene graph approach — Scene, Camera, Renderer — maps cleanly to how I think about spatial design, and the MeshPhysicalMaterial with clearcoat support was essential for getting the latte cup material right.

Canvas 2D API

Rather than sourcing image files for labels and panel textures, I generated everything procedurally using the Canvas 2D API and wrapped the results in THREE.CanvasTexture. This means the app has zero external image dependencies and textures can be tweaked live in code. The espresso machine display and the latte label are both drawn this way.

GLSL Custom Shader

The espresso machine body uses a handwritten ShaderMaterial. The vertex shader passes UV coordinates and view-space normals to the fragment shader, which computes a Fresnel term and a time-animated sine-wave shimmer. I got the Fresnel formula from WebGL Fundamentals and then adapted it — I spent a while tuning the power value and shimmer frequency until it felt like metal rather than plastic.

jQuery

I used jQuery's fadeOut/fadeIn transition to smooth the model info update in the left panel when switching between brews. It's a small detail but it makes the content switch feel intentional rather than abrupt.

Deeper Understanding Features

  1. Custom GLSL ShaderMaterial — Fresnel reflectance with animated UV shimmer on the espresso machine body. Written from scratch in GLSL with time-based sine wave displacement.
  2. Canvas 2D API Texture — Pressure gauge display drawn procedurally at runtime using HTML5 Canvas 2D API and wrapped as THREE.CanvasTexture. Zero external image dependencies.
  3. GLTFLoader + Blender GLB — Coffee shop interior modelled in Blender 5.1 and exported as glTF 2.0 GLB. Loaded asynchronously using THREE.GLTFLoader with DoubleSide material flags and shadow casting.
  4. jQuery Animated Transitions — Model info panel uses jQuery fadeOut/fadeIn for smooth content switching between models. Camera lerp animation using requestAnimationFrame for smooth view transitions.

04

Design Decisions

The visual identity came from thinking about what independent coffee shops actually look like — not chain cafés, but the kind of place with handwritten menus and mismatched chairs.

  • Colour palette: Deep espresso brown (#2C1A0E) for the header and footer because it reads immediately as a coffee brand. Terracotta (#C1440E) for interactive accents — it has that fired-clay, artisan quality that specialty coffee branding often reaches for. Off-white (#FAF6F0) for the background because pure white would feel clinical.
  • Typography: Playfair Display for headings because it has the same slightly editorial quality I see in good café branding — it feels considered. Lato for UI text because it's neutral enough to stay out of the way.
  • Panel layout: The three-column structure was inspired by professional 3D software interfaces — info on the left, canvas in the centre, controls on the right. It gives the app a tool-like feel rather than a webpage feel.
  • Glass panels: The side panels use backdrop-filter blur with semi-transparent backgrounds so the 3D model is subtly visible through them. On the coffee theme this reinforces the idea of a window into the space.
  • Chalkboard header: Making the header dark espresso brown rather than light was a deliberate decision to evoke a café chalkboard. The terracotta accent colour on nav links and active states reads like chalk marks.

05

Testing

I tested across Chrome, Firefox, and Safari, and on both desktop and an iPhone. A few things needed fixing:

  • Canvas resize: On window resize the renderer and camera aspect ratio update via the resize event listener in scene.js — without this the model stretched on mobile rotation.
  • Wireframe on GLB models: The moon GLB has nested child meshes. Using mesh.traverse() on the parent group ensures the wireframe flag reaches every child regardless of nesting depth.
  • Drag vs click conflict: The isDragging flag gets reset on mouseup and mouseleave so releasing the mouse outside the canvas doesn't lock the rotation.
  • GLB load timing: The GLTFLoader callback is async, so I had to add the loaded scene to currentMesh rather than to a returned group — otherwise the model was added to a group that had already been removed from the scene.
  • DoubleSide on the interior sphere: Without THREE.DoubleSide, the inside faces of the sphere mesh rendered black. Setting it in the loader callback fixed the visual immediately.

07

Accessibility

  • All interactive elements (buttons, toggle switches, links, product cards) have visible :focus-visible outlines using the terracotta accent colour so keyboard users can track focus.
  • Decorative elements (background glow, drag-hint icon, card thumbnails) are marked with aria-hidden="true" so screen readers skip them.
  • Semantic HTML is used throughout — <header>, <nav>, <aside>, <section>, <h1>–<h2> — giving the document a logical structure for assistive technologies.
  • Product card buttons have descriptive aria-label attributes so screen readers announce "Load Espresso Machine model" rather than reading the visual card text out of context.
  • Colour contrast between the body text (#2C1A0E) and the warm background (#FAF6F0) exceeds the WCAG AA ratio of 4.5:1. Interactive focus outlines use terracotta (#C1440E) which remains visible against both light and dark surfaces.
  • Font sizes are set in relative units (rem / em) so they scale with the user's browser font size setting.
